# Reverse Proxies and Server Configuration

## AWS Overview

AWS is Amazon's **cloud** service.

It lets you:
- Rent servers
- Manage domains
- Upload objects (mp4 files, JPGs, MP3s, etc.)
- Autoscale servers
- Create Kubernetes (k8s) clusters

The offering we will be focusing on today is **renting servers**.

## Domain Configuration Cases

### Case 1: Using Amazon's Given Address (EC2 Public IP or Elastic IP)

**When to use:** You don't have a custom domain and want to use AWS-provided IP address.

**Steps:**

1. **Get your EC2 instance's public IP:**
   - Go to EC2 Console → Instances → Select your instance
   - Copy the **Public IPv4 address** (e.g., `54.123.45.67`)

2. **Or use Elastic IP (recommended for production):**
   ```bash
   # In AWS Console:
   # EC2 → Elastic IPs → Allocate Elastic IP address
   # Associate it with your instance
   ```

3. **Nginx Configuration:**
   - Use the IP address directly in `server_name` or use `_` (catch-all)
   - No DNS configuration needed

**Nginx Config Example:**

```nginx
server {
    listen 80;
    server_name _;  # Catch-all, accepts any domain/IP
    
    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

**Access:** `http://54.123.45.67` (your EC2 public IP)

---

### Case 2: Using Purchased Domain

**When to use:** You own a custom domain (e.g., `example.com`) and want to point it to your EC2 instance.

**Steps:**

1. **Get your EC2 instance's public IP or Elastic IP**
   - Same as Case 1

2. **Configure DNS Records:**
   
   **Option A: Using AWS Route 53 (Recommended)**
   - Go to Route 53 → Hosted Zones
   - Create a hosted zone for your domain
   - Create an **A record**:
     - **Name:** `@` (for root domain) or `www` (for subdomain)
     - **Type:** A
     - **Value:** Your EC2 public IP or Elastic IP
     - **TTL:** 300 (or as needed)
   - Update your domain's nameservers at your registrar to Route 53 nameservers

   **Option B: Using External DNS Provider (e.g., GoDaddy, Namecheap)**
   - Log into your domain registrar
   - Go to DNS Management
   - Add an **A record**:
     - **Host:** `@` (root) or `www` (subdomain)
     - **Points to:** Your EC2 public IP or Elastic IP
     - **TTL:** 300 seconds
   - Save changes (DNS propagation can take 5 minutes to 48 hours)

3. **Verify DNS Resolution:**
   ```bash
   # Check if DNS is pointing correctly
   dig example.com
   # or
   nslookup example.com
   ```

4. **Nginx Configuration:**

```nginx
server {
    listen 80;
    server_name example.com www.example.com;  # Your domain names
    
    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

**Access:** `http://example.com` (your custom domain)

## Complete Nginx Setup

### Method 1: Using sites-available/sites-enabled (Recommended)

1. **Create configuration file:**

```bash
sudo nano /etc/nginx/sites-available/yourdomain.com
```

2. **Add configuration:**

```nginx
server {
    listen 80;
    
    # For custom domain:
    server_name yourdomain.com www.yourdomain.com;
    
    # For AWS IP only (use one of these):
    # server_name _;  # Catch-all
    # server_name 54.123.45.67;  # Specific IP
    
    # Increase body size limit (for file uploads)
    client_max_body_size 100M;
    
    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        
        # WebSocket support
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        
        # Standard headers
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # Timeouts
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
        
        # Cache bypass for WebSocket
        proxy_cache_bypass $http_upgrade;
    }
    
    # Optional: Serve static files directly
    location /static {
        alias /var/www/yourdomain.com/static;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

3. **Enable the site:**

```bash
# Create symbolic link
sudo ln -s /etc/nginx/sites-available/yourdomain.com /etc/nginx/sites-enabled/

# Remove default site (optional)
sudo rm /etc/nginx/sites-enabled/default
```

4. **Test configuration:**

```bash
sudo nginx -t
```

5. **Reload Nginx:**

```bash
sudo systemctl reload nginx
# or
sudo nginx -s reload
```

### Method 2: Direct Configuration (Alternative)

Edit the main config file:

```bash
sudo nano /etc/nginx/nginx.conf
```

Add server block inside `http {}` block:

```nginx
http {
    # ... existing config ...
    
    server {
        listen 80;
        server_name yourdomain.com;
        
        location / {
            proxy_pass http://localhost:3000;

            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_cache_bypass $http_upgrade;
        }
    }
}
```

## SSL/TLS Setup with Let's Encrypt (HTTPS)

### Prerequisites

- Domain name pointing to your server (Case 2)
- Port 80 and 443 open in Security Groups

### Install Certbot

```bash
sudo apt install certbot python3-certbot-nginx -y
```

### Obtain SSL Certificate

**For custom domain:**

```bash
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com
```

**Follow prompts:**
- Enter email address
- Agree to terms
- Choose whether to redirect HTTP to HTTPS (recommended: Yes)

### Auto-renewal Setup

Certbot automatically sets up a cron job, but verify:

```bash
# Test renewal
sudo certbot renew --dry-run

# Check renewal timer
sudo systemctl status certbot.timer
```

### Updated Nginx Config (with SSL)

After Certbot, your config will look like:

```nginx
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;
    return 301 https://$server_name$request_uri;  # Redirect HTTP to HTTPS
}

server {
    listen 443 ssl http2;
    server_name yourdomain.com www.yourdomain.com;
    
    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;
    
    # SSL configuration (added by Certbot)
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
    
    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

## Security Configuration

### 1. Configure Firewall (UFW)

```bash
# Check status
sudo ufw status

# Allow SSH (important - do this first!)
sudo ufw allow 22/tcp

# Allow HTTP and HTTPS
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# Enable firewall
sudo ufw enable

# Check status again
sudo ufw status verbose
```

### 2. AWS Security Groups

In EC2 Console → Security Groups → Your Security Group:

**Inbound Rules:**
- **Type:** SSH, **Port:** 22, **Source:** Your IP (or 0.0.0.0/0 for testing)
- **Type:** HTTP, **Port:** 80, **Source:** 0.0.0.0/0
- **Type:** HTTPS, **Port:** 443, **Source:** 0.0.0.0/0
- **Type:** Custom TCP, **Port:** 3000, **Source:** 127.0.0.1/32 (only localhost)

**Outbound Rules:**
- Allow all (default)

### 3. Harden SSH

```bash
sudo nano /etc/ssh/sshd_config
```

**Recommended settings:**

```bash
# Disable root login
PermitRootLogin no

# Disable password authentication (use keys only)
PasswordAuthentication no

# Change default port (optional, for security)
# Port 2222

# Restart SSH
sudo systemctl restart sshd
```

### 4. Fail2Ban (Protect against brute force)

```bash
sudo apt install fail2ban -y
sudo systemctl enable fail2ban
sudo systemctl start fail2ban
```

## Common Nginx Configurations

### Multiple Applications on Same Server

```nginx
# App 1 on port 3000
server {
    listen 80;
    server_name app1.yourdomain.com;
    
    location / {
        proxy_pass http://localhost:3000;
        # ... proxy headers ...
    }
}

# App 2 on port 3001
server {
    listen 80;
    server_name app2.yourdomain.com;
    
    location / {
        proxy_pass http://localhost:3001;
        # ... proxy headers ...
    }
}
```

### Rate Limiting

```nginx
# In http block
limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;

server {
    # ...
    location /api {
        limit_req zone=api_limit burst=20 nodelay;
        proxy_pass http://localhost:3000;
        # ... proxy headers ...
    }
}
```

### Gzip Compression

```nginx
# In http block
gzip on;
gzip_vary on;
gzip_min_length 1024;
gzip_types text/plain text/css text/xml text/javascript application/x-javascript application/xml+rss application/json;
```

## Troubleshooting

### Check Nginx Logs

```bash
# Error logs
sudo tail -f /var/log/nginx/error.log

# Access logs
sudo tail -f /var/log/nginx/access.log
```

### Check Application Logs

```bash
# PM2 logs
pm2 logs

# System logs
sudo journalctl -u nginx -f
```

### Common Issues

1. **502 Bad Gateway:**
   - Check if application is running: `pm2 status`
   - Check if port matches: `netstat -tlnp | grep 3000`
   - Check application logs

2. **DNS not resolving:**
   - Verify DNS records: `dig yourdomain.com`
   - Wait for DNS propagation (can take up to 48 hours)

3. **Connection refused:**
   - Check Security Groups (ports 80, 443)
   - Check UFW firewall: `sudo ufw status`
   - Check if Nginx is running: `sudo systemctl status nginx`

## Summary

**For AWS IP only:**
- Use `server_name _;` in Nginx config
- Access via `http://<ec2-public-ip>`
- No DNS configuration needed

**For custom domain:**
- Point DNS A record to EC2 IP
- Use `server_name yourdomain.com;` in Nginx config
- Access via `http://yourdomain.com`
- Set up SSL for HTTPS

**Key Commands:**
```bash
sudo nginx -t                    # Test config
sudo systemctl reload nginx      # Reload Nginx
pm2 start app.js                 # Start app
pm2 logs                         # View logs
sudo ufw status                  # Check firewall
```
